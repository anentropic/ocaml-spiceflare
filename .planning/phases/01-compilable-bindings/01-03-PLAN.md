**Step D: Add emit_tests function to lib/emit.ml**

Add a new function to `emit.ml` that generates one test file per output file. Each test file:
1. Opens the corresponding bindings module
2. For each submodule, emits a `type x_t = Module.t` alias to verify type resolution
3. For each External item in each submodule, emits a `let _f = Module_name.external_name` binding to force type-checking of the external's full declared signature (per TEST-01 requirement)

Add after the existing `emit_all` function:

```ocaml
(** Generate a compile-checking test file for a binding output file.
    The test file references types and externals with explicit annotations
    to trigger Melange type-checking of cross-module references and
    external signatures. *)
let gen_test_content (f : output_file) : string =
  let buf = Buffer.create 1024 in
  let bprintf = Printf.bprintf in
  let module_name =
    (* Derive module name from filename: "streams.ml" -> "Streams" *)
    let stem = Filename.chop_extension f.of_filename in
    String.capitalize_ascii stem
  in
  bprintf buf "(* Generated compile-checking test for %s *)\n\n" f.of_filename;
  bprintf buf "open Cf_workers_bindings.%s\n\n" module_name;
  (* For each submodule, reference its type t and externals *)
  List.iter
    (fun (m : ocaml_module) ->
       let safe_prefix =
         String.lowercase_ascii m.m_name |>
         String.map (fun c ->
           if (c >= 'a' && c <= 'z') || (c >= '0' && c <= '9') || c = '_' then c
           else '_')
       in
       (* Verify type t is resolvable *)
       bprintf buf "(* Verify %s.t is resolvable *)\n" m.m_name;
       bprintf buf "type %s_t = %s.t\n\n" safe_prefix m.m_name;
       (* Verify each external's full signature is type-correct *)
       List.iter
         (fun item ->
            match item with
            | External { e_name; _ } ->
              bprintf buf "let _%s_%s = %s.%s\n"
                safe_prefix e_name m.m_name e_name
            | _ -> ())
         m.m_items;
       bprintf buf "\n")
    f.of_modules;
  Buffer.contents buf

(** Write test files alongside binding files, in a parallel directory. *)
let emit_tests ~dir (files : output_file list) =
  List.iter
    (fun f ->
       let test_filename =
         let stem = Filename.chop_extension f.of_filename in
         stem ^ "_test.ml"
       in
       let path = Filename.concat dir test_filename in
       let content = gen_test_content f in
       let oc = open_out path in
       output_string oc content;
       close_out oc;
       Printf.printf "Wrote test %s\n" path)
    files
```

**Step E: Fix compile errors iteratively (max 3 cycles)**

After regeneration, Melange compilation may reveal remaining issues. Common expected issues:

1. **Some cross-module references may still be wrong** -- If `file_module_of` returns incorrect module names for some edge cases, look at the error messages to identify which types are unresolved. Fix by adjusting `transform.ml` or `resolve.ml` as needed.

2. **Type parameter names may collide with module names in rare cases** -- If a type parameter `T` shadows a declaration `T`, the type_params check (added in Plan 01) should handle this. But check for any cases where `type_params` wasn't threaded correctly.

3. **Cycle-related issues from topo sort** -- If the topo sort emitted warnings about cycles, some forward references may still exist. These need manual inspection -- the generated module with the cycle may need a forward type declaration added to `emit.ml`.

4. **melange.emit may discover issues the library stanza alone wouldn't** -- Because `(library (modes melange))` only checks types when something depends on it, but `melange.emit` triggers full compilation.

5. **External let-bindings in test files may reveal signature mismatches** -- The `let _f = Module.external_name` bindings force the compiler to verify the external's full type. If a generated external has a wrong type, this will surface as a test compilation error.

For each compile error:
- Read the error message
- Identify the generated `.ml` file and line
- Trace back to which IR declaration / codegen function produced it
- Fix the codegen, not the generated file (the generated file will be overwritten on next run)
- Regenerate and re-test

**IMPORTANT: Limit to 3 fix-regenerate-compile cycles.** If errors remain after 3 cycles:
- Document the remaining errors (count, categories, example messages) in the SUMMARY

- Note which codegen areas need further work
