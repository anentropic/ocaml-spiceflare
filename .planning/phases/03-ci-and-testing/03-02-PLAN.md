This task configures branch protection on main using the GitHub REST API via `gh` CLI. It requires no file changes -- it is a remote API call.

**IMPORTANT CAVEAT:** The check context names (`build (spiceflare)`, `build (spiceflare-codegen)`, `melange-check`) are the EXPECTED names based on how GitHub Actions names matrix jobs. These MUST be verified after the first CI run. If the CI has not yet run (i.e., the updated ci.yml from Plan 01 has not been pushed), this task should note that verification is deferred.

**Step 1: Verify actual check context names (if CI has run)**

If the updated CI workflow has been pushed and run at least once, verify the check names:

```bash
gh api /repos/{owner}/{repo}/commits/$(git rev-parse HEAD)/check-runs \
  --jq '.check_runs[].name'
```

If the CI has NOT yet run with the new workflow, skip this step and use the expected names below. The user will need to verify after the first push.

**Step 2: Set branch protection**

Run exactly this command:

```bash
gh api -X PUT /repos/{owner}/{repo}/branches/main/protection \
  --input - <<'EOF'
{
  "required_status_checks": {
    "strict": true,
    "checks": [
      {"context": "build (spiceflare)"},
      {"context": "build (spiceflare-codegen)"},
      {"context": "melange-check"}
    ]
  },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null
}
EOF
```

Notes:
- `strict: true` means the branch must be up-to-date with base before merging (require branches to be up to date).
- `enforce_admins: false` allows repo owner to bypass in emergencies (per research recommendation for personal project).
- `required_pull_request_reviews: null` means no PR review requirement (solo developer).
- `restrictions: null` means no push restrictions.
- The `{owner}/{repo}` placeholders are auto-resolved by `gh` CLI from the git remote.

**Step 3: Verify the protection was set**

```bash
gh api /repos/{owner}/{repo}/branches/main/protection \
  --jq '.required_status_checks.checks[].context'
```

This should output:
```
build (spiceflare)
build (spiceflare-codegen)
melange-check
```

If the context names don't match (e.g., GitHub prefixes them with workflow name like `CI / build (spiceflare)`), update the protection with the correct names using the same PUT command with corrected context values.
